## 1. Analysis of current implementation

### A. Speaker routing

The supplied backend file does not control speaker routing. Audio output is controlled by the browser/device through the frontend `<audio>` or `<video>` elements.

Typical causes of the current speaker behavior are:

- Remote media is assigned to a `<video>` element without `playsInline`.
- The frontend explicitly enables speaker routing through a native/WebRTC plugin.
- A media element is created without configuring an audio output device.
- Mobile browser behavior is being treated as equivalent to desktop browser behavior.

Important limitations:

- `HTMLMediaElement.setSinkId()` is supported mainly by Chromium-based desktop browsers and some Android browsers.
- iOS Safari generally does not provide a reliable web API for selecting the earpiece versus loudspeaker.
- `setSinkId("default")` selects the system default output; it does not universally mean “earpiece.”
- On native mobile wrappers such as Capacitor or React Native, speaker routing usually requires a native audio-session/plugin implementation.

Therefore, the implementation should:

1. Use an application-level `speakerEnabled` state.
2. Default it to `false`.
3. Apply the state to every remote audio/video element.
4. Use `setSinkId()` where supported.
5. Use a native audio-routing adapter for mobile apps where browser APIs are unavailable.
6. Treat the browser fallback as best effort and communicate unsupported behavior in the UI if necessary.

### B. One-to-one call ending

The required behavior means the backend must be authoritative:

- When either participant ends a one-to-one call, the server emits a call-ended event to both participants.
- The server must remove the call from its active-call registry.
- Both frontend clients must close peer connections, stop local media, detach remote media, and reset call UI state.
- The second participant must not need to click “End Call.”

The important issue is that signaling a peer connection close is not enough. `RTCPeerConnection.close()` only affects the local browser. A Socket.IO event must be sent to the other participant.

### C. Group call ending

Group calls require different semantics:

- A participant leaving must only be removed from the group.
- Other participants remain connected.
- The call ends globally only when the last participant leaves.
- The backend should track active participants by `callId`, not infer state only from Socket.IO room membership.
- Disconnects and browser refreshes must be treated as participant leaves.

Do not reuse one-to-one “end call for everyone” logic for group calls.

### D. Backend state requirements

The provided `socket/Socketmanager.js` is large and currently appears to contain unrelated messaging and transcription logic. Add call lifecycle logic in a dedicated section or extract it into a service such as:

```text
services/callPresenceService.js
```

For a single Node.js process, an in-memory registry is acceptable initially. For multiple backend instances, use Redis or another shared store because Socket.IO rooms alone are not sufficient for reliable participant accounting.

### Step 2: Add an active-call registry on the backend

Create:

```js
// services/activeCallRegistry.js
const calls = new Map();

/*
Map structure:

callId -> {
  callType: "direct" | "group",
  participants: Map<userId, {
    userId,
    socketIds: Set<string>
  }>,
  createdAt
}
*/

function ensureCall(callId, callType) {
  let call = calls.get(callId);

  if (!call) {
    call = {
      callId,
      callType,
      participants: new Map(),
      createdAt: Date.now(),
    };

    calls.set(callId, call);
  }

  return call;
}

function addParticipant(callId, callType, userId, socketId) {
  const call = ensureCall(callId, callType);

  let participant = call.participants.get(String(userId));

  if (!participant) {
    participant = {
      userId: String(userId),
      socketIds: new Set(),
    };

    call.participants.set(String(userId), participant);
  }

  participant.socketIds.add(socketId);

  return call;
}

function removeParticipant(callId, userId, socketId) {
  const call = calls.get(callId);

  if (!call) {
    return null;
  }

  const participant = call.participants.get(String(userId));

  if (participant) {
    if (socketId) {
      participant.socketIds.delete(socketId);
    }

    if (!socketId || participant.socketIds.size === 0) {
      call.participants.delete(String(userId));
    }
  }

  if (call.participants.size === 0) {
    calls.delete(callId);
  }

  return call;
}

function getCall(callId) {
  return calls.get(callId);
}

function deleteCall(callId) {
  return calls.delete(callId);
}

module.exports = {
  addParticipant,
  removeParticipant,
  getCall,
  deleteCall,
};
```

Use user IDs rather than only socket IDs. This prevents one user opening multiple tabs or reconnecting from being incorrectly treated as multiple participants.

For a horizontally scaled deployment, replace this map with Redis-backed state.

        return ack?.({
          ok: false,
          error: "Missing callId",

        return ack?.({ ok: true });

      ack?.({ ok: true });

      console.error("call:end failed", error);

      ack?.({
        ok: false,
        error: "Unable to end call",
      });

    try {
      const { callId, callType } = payload;

      if (!callId) {
        return ack?.({
          ok: false,
          error: "Missing callId",
        });
      }

      const call = activeCallRegistry.getCall(callId);

      if (!call) {
        return ack?.({ ok: true });
      }

      // A direct call should not use call:leave as a local-only operation.
      // It must end for both users.
      if (call.callType === "direct" || callType === "direct") {
        io.to(`call:${callId}`).emit("call:ended", {
          callId,
          callType: "direct",
          endedBy: userId,
          reason: "participant-left",
        });

        ack?.({ ok: true });
        return;

      activeCallRegistry.removeParticipant(callId, userId, socket.id);

      socket.leave(`call:${callId}`);

      socket.to(`call:${callId}`).emit("call:participant-left", {
        callId,
        participantId: userId,
        reason: "participant-left",
      });

      const updatedCall = activeCallRegistry.getCall(callId);

      if (!updatedCall || updatedCall.participants.size === 0) {
        io.to(`call:${callId}`).emit("call:ended", {
          callId,
          callType: "group",
          endedBy: userId,
          reason: "last-participant-left",
        });

        activeCallRegistry.deleteCall(callId);
      }

      ack?.({ ok: true });
    } catch (error) {
      console.error("call:leave failed", error);
      ack?.({ ok: false });
    }
  });
});

#### Important correction

Do not send a direct-call `call:ended` event only to the remote socket. Send it to the entire call room:

```js
io.to(`call:${callId}`).emit("call:ended", payload);
```

This ensures the initiating browser also receives the same authoritative event and performs the same cleanup.

### Step 4: Handle socket disconnects

A browser can close, refresh, lose connectivity, or kill the app without clicking the end button.

Add disconnect handling:

```js
socket.on("disconnect", () => {
  const activeCalls = Array.from(socket.data.activeCalls || []);

  for (const callId of activeCalls) {
    const call = activeCallRegistry.getCall(callId);

    if (!call) {
      continue;
    }

    if (call.callType === "direct") {
      io.to(`call:${callId}`).emit("call:ended", {
        callId,
        callType: "direct",
        endedBy: userId,
        reason: "disconnect",
      });

      activeCallRegistry.deleteCall(callId);
      continue;
    }

    activeCallRegistry.removeParticipant(
      callId,
      userId,
      socket.id
    );

    socket.to(`call:${callId}`).emit("call:participant-left", {
      callId,
      participantId: userId,
      reason: "disconnect",
    });

    const updatedCall = activeCallRegistry.getCall(callId);

    if (!updatedCall || updatedCall.participants.size === 0) {
      io.to(`call:${callId}`).emit("call:ended", {
        callId,
        callType: "group",
        endedBy: userId,
        reason: "last-participant-disconnected",
      });

      activeCallRegistry.deleteCall(callId);
    }
  }
});
```

If you use multiple socket connections for the same user, only remove the user after all of that user's sockets have disconnected.

For production, also add a grace period for temporary network disconnects. Otherwise, a short mobile network transition may end a direct call immediately.
